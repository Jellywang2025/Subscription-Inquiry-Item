## 首轮审图

[打开审图页](review.html)，每组对照 1920 × 1080 与 1080 × 1920。核对账号可区分、数字优先级、配置操作可定位、表单文字清楚、授权进度可理解。另在 390 × 844 检查单列与横向滚动。选择接受的截图后记录核准人、日期及调整项。

[打开原型](prototype/index.html) 可完成以下本地交互。示例账号在当前页面内存中修改，浏览器重开会加载初始示例，网址保留总览和配置页的筛选条件。

| 场景 | 操作与检查 |
| --- | --- |
| 搜索与空态 | 搜「工作号」并筛选 DeepSeek，复制网址重开。改搜无匹配词并点清除。打开[首次无配置](prototype/index.html?demo=empty)并添加第一条。 |
| 查询失败 | 打开[失败示例](prototype/index.html?demo=failure)，观察曾成功或从未成功的卡片，点立即刷新。 |
| 配置与删除 | 进入配置管理，编辑任一账号，取消一次删除后再确认删除。核对其他账号仍可操作。 |
| 设备码 | 打开[授权过期示例](prototype/index.html?view=auth&id=codex-work&step=expired)，重新获得示例设备码，点击「我已完成授权」查看模拟结果。该状态用于视觉评审。 |
| 更换密钥 | 在 DeepSeek 表单输入 `bad-demo-key` 观察失败，再输入 `mock-deep-9876` 观察末四位。添加 MiMo 时使用 `mock-mimo-0952`。 |
| 窗口缩放 | 在密钥表单输入示例值，缩成单列后再次展开，检查当前页面及输入。 |

## 服务器成品复检

- DSH 调用独立 `codex-tester` 从服务器的登录、总览和配置页面验证 AC-01 至 AC-09，并记录候选提交及自动化证据。
- 老板先按相同视口核对已核准截图，再用自己的真实账号访问目标服务器。分别通过官方设备码绑定两个 Codex 账号，对照各自额度窗口、数值和重置时间。实际核对 DeepSeek 与 MiMo 的同币种余额。
- 在服务器确认新增、编辑、删除、密钥验证后替换、关闭网页期间的后台刷新、重启后数据保留及筛选书签恢复。记录实际通过项、失败项和证据。
