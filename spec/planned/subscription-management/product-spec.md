# 个人订阅管理 · 产品 Spec

- 版本 `0.2.0`
- 状态 `planned`，首轮视觉评审中
- 需求方确认记录 2026-11-26。已逐项确认负责人、默认展示、空态、书签、网页增删改查和线上管理方式，以及横竖屏导航与首轮审图范围。

## 使用目标

管理员在服务器网页集中管理自己的 Codex、DeepSeek 和 MiMo 账号。每个账号有独立的名称、连接配置和额度或余额结果。同一平台可配置多个账号。所有账号默认归管理员本人。首页按平台分组，每个账号一张卡。Codex 显示官方返回的额度窗口及重置时间，可登记套餐、费用、币种、续费周期和下次续费日。DeepSeek 显示 API 账户可用余额，MiMo 显示 SK 充值账户可用余额。新版入口覆盖这三类账号。

## 业务行为

| 验收编号 | 用户操作 | 预期结果 |
| --- | --- | --- |
| AC-01 | 访问服务器并登录 | 单管理员通过登录进入总览。未登录的受保护页面要求登录，登录后还原所访问的筛选链接。 |
| AC-02 | 在总览打开两个 Codex 账号及两个 API 余额账号 | 按平台分组，每个账号独立展示额度或余额、状态及更新时间。Codex 明细含手填的订阅信息。真实零额显示为零。 |
| AC-03 | 按名称搜索并筛选平台，保存当前网址后重开 | 链接还原平台和搜索词，并读取当前数据。打开无筛选的总览链接展示全部账号。 |
| AC-04 | 访问无配置、无匹配、查询失败场景 | 无配置时可添加第一条。无匹配时可清除条件。查询失败保留卡片及原因，已有成功结果时保留数值和原时间。 |
| AC-05 | 从配置管理新增、查找、编辑和删除账号 | 修改只作用于选定账号。删除确认提示平台和名称，确认后移除记录、凭据和缓存，并停止该账号查询。其他记录和配置保留。 |
| AC-06 | 在服务器为两个 Codex 账号分别授权，模拟设备码过期后重新授权 | 网页发起官方设备码登录，提示授权进度与过期重试。两账号的服务器登录状态和查询结果相互隔离。登录失效时可再次授权。 |
| AC-07 | 新增 DeepSeek 或 MiMo 账号，再尝试替换密钥 | 保存凭据后仅显示末四位。成功验证新密钥后替换，验证失败保留旧凭据和连接。 |
| AC-08 | 关闭网页等待下一轮刷新，再打开网页或点击立即刷新 | 服务器默认每 15 分钟查询，管理员可在网页修改间隔。正常来源独立更新，失败来源提示原因。服务重启后账号、配置和上次成功结果仍可访问。 |
| AC-09 | 同一页面横屏、竖屏对照并缩放至手机宽度 | 导航、卡片列数、账号操作和表单遵循已核准的 UI Spec。缩放过程保留筛选和输入。 |

## 上线与验收

线上网页承担账号与刷新配置。服务端保存登录状态和密钥，浏览器读取展示字段及密钥末四位。Codex 用官方设备码登录并读取额度。[登录说明](https://learn.chatgpt.com/docs/auth#preferred-device-code-authentication-beta) · [额度接口](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)

以 [视觉草案](ui-spec.md) 和 [验收基线](acceptance.md) 完成首轮评审。核准后通过对应版本及提交交接实施。真实账号和目标服务器用于最终复检。
