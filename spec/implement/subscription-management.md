## 1. 谁使用，管理什么

管理员从浏览器登录部署在服务器上的个人订阅管理系统，查看各账号还剩多少额度或余额，并在网页上管理连接、付费信息和刷新间隔。系统采用单管理员登录，所有订阅默认归管理员本人，无须填写负责人。

一条配置对应**一个平台账号**。通常每个平台配置一个账号即可使用。新增时由管理员自由填写用于展示和搜索的名称，改名保留原连接。系统不设置、询问或从名称推断“工作号／个人号”等用途分类。同一平台以后有第二个账号时，仍从「添加订阅」新增并独立连接。每个账号分别保存连接、查询结果、成功时间和适用的订阅信息。配置入口和总览覆盖 Codex、DeepSeek 和 MiMo 三个平台，移除旧版 ChatGPT 聊天卡片及官方聊天入口。Codex 授权页仍提供前往 OpenAI 完成登录的入口。

| 平台 | 在网页上配置 | 总览先看什么 | 展开后看什么 |
| --- | --- | --- | --- |
| Codex | 账号名称、官方设备码授权。可手填套餐、费用、币种、续费周期、下次续费日 | 各额度窗口的剩余比例及各自的重置时间，附连接或刷新状态、更新时间 | 套餐、费用与续费信息 |
| DeepSeek | 账号名称、DeepSeek API Key | 按官方返回币种分别显示可用余额及更新时间 | 同币种的充值余额、赠金等官方明细 |
| MiMo | 账号名称、MiMo SK | 充值账号的当前可动用余额及更新时间 | 官方返回的现金、赠金、可用授信和冻结金额 |

Codex 按官方返回的窗口展示。官方给出已用比例时，剩余比例按 100% 减已用比例计算。缺少重置时间的窗口提示“未提供”。MiMo 沿用已确认的充值账户口径，当前可动用金额取官方总额减冻结金额，最低为零。DeepSeek 和 MiMo 的充值账号无需填写续费日。[既有额度与余额口径](../archived/personal-quota-dashboard.md)

## 2. 网页操作和数据行为

**打开与查找。** 登录后默认进「订阅总览」，按 Codex、DeepSeek、MiMo 分组，每个已配置账号一张卡。总览与配置管理都支持按账号名称搜索、按平台筛选。书签保存当前页面、平台和搜索词，重开时按这些条件读取最新可用结果。直接打开首页地址时显示全部订阅。需要重新登录时，登录成功后回到原先要访问的视图。

**新增、编辑与删除。** 第一个账号和后续账号都从「添加订阅」选择平台、填写自定义名称并连接。只添加一个账号就能完成查看、刷新和管理。在「配置管理」中可查看、编辑或删除选中的记录。编辑账号名或付费字段时可保留原连接。删除确认框显示平台及账号名，取消后保留配置，确认后清除该条配置、凭据与缓存并停止其查询。删除只作用于看板内该账号，平台账户及实际订阅继续有效。

**Codex 授权。** 从所选账号发起设备码授权。页面显示账号名、一次性设备码、有效期、复制操作、官方授权页入口及当前进度。管理员在 OpenAI 官方页面登录目标账号并确认，服务器收到成功结果后显示已连接。设备码过期可在该页重新获取，已保存的登录失效可从该账号重新授权。服务器为每个 Codex 账号分别保存登录状态并查询额度。[官方设备码登录](https://learn.chatgpt.com/docs/auth#preferred-device-code-authentication-beta) · [官方额度接口](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)

**API 密钥。** 在网页输入 DeepSeek API Key 或 MiMo SK，服务端完成验证并保存。保存后只展示末四位及连接状态。更换时先验证新 Key，成功后替换。验证失败提示原因并保留原连接。只修改账号名称时可将新密钥留空。真实凭据与提供方登录状态保存在服务器端。

**刷新。** 服务器默认每 15 分钟查询，网页关闭后继续运行。管理员可在配置管理修改刷新间隔，也可在总览立即刷新。各账号独立更新，展示实际成功时间。服务重启后可读取账号、配置及上次成功结果。

| 页面状态 | 用户看到的结果 | 可执行操作 |
| --- | --- | --- |
| 从未配置或已删除全部订阅 | 首次使用空态 | 添加第一条订阅 |
| 已有订阅，当前搜索或筛选无匹配 | 显示没有匹配的订阅 | 清除条件，恢复全部账号 |
| 某账号首次查询失败 | 保留卡片，显示失败原因及暂无可用结果 | 立即刷新，或按原因更新该账号的连接 |
| 曾查询成功，本轮失败 | 保留原数值和原成功时间，标明刷新失败及原因 | 再次刷新。成功后更新数值与时间、清除失败状态 |
| 查询成功且余额为零 | 显示官方返回币种及 0.00 | 展开余额明细 |

## 3. 已核准的视觉和响应式规则

「订阅总览」用于看额度与余额，「配置管理」用于管理账号。桌面首页右上角使用深色「添加订阅」主按钮。界面采用黑白层级、清晰的大号数值和留白。卡片、表单、导航和状态以本节规则及下列四组截图为视觉基线。

| 浏览器实际可用宽度 | 导航 | 内容布局 |
| --- | --- | --- |
| 1251 CSS px 起 | 230 px 左侧栏，依次为订阅总览、配置管理 | 总览最多三列，两账号分组可各占半行。配置列表显示名称、平台、连接状态、续费日或密钥末四位及行内操作。 |

## 4. 验收条件

沿用已确认的九个 AC 编号。下列操作从服务器网页发起。自动化可使用可控的平台回执，真实账号及后台运行另在目标服务器核对。

| 编号 | 操作场景 | 通过条件 | 验证方式 |
| --- | --- | --- | --- |
| AC-01 | 未登录时分别打开首页和带筛选的受保护网址，再以管理员登录 | 先要求登录。首页进入全部订阅，筛选网址恢复原视图。 | 浏览器契约测试 |
| AC-02 | 先仅配置一个自命名账号查看卡片，再按需添加其他平台和同平台账号，展开各自明细 | 单账号即可使用。每个已配置账号一张卡，显示管理员填写的名称。窗口、百分比、重置时间、金额及币种符合第 1 节。真实零额可与缺少结果区分。 | 可控回执与真实账号对照 |
| AC-03 | 筛选 DeepSeek 并搜索已自定义的名称（例如「青岚」），保存网址。更改来源数据并完成刷新后，重开该网址，再直接打开首页 | 重开仍按原条件展示最新可用结果。首页恢复全部账号。 | 浏览器契约测试 |
| AC-04 | 分别触发无配置、无匹配、首次查询失败及已有成功数据后查询失败，再恢复查询 | 四种状态按第 2 节分别显示，失败只影响对应卡片，恢复后更新数据及成功时间。 | 浏览器契约测试及可控回执 |
| AC-05 | 自命名第一个账号并单独使用，再从同一入口新增第二个账号。按名称查找和改名，先取消删除，再确认删除一条 | 配置可回读，其他账号独立。取消保留配置，确认后该条记录、凭据和缓存移除，后续刷新跳过该账号。 | 浏览器契约测试与重开复检 |
| AC-06 | 先为一个自命名 Codex 账号授权。通过同一入口增配第二个测试账号，覆盖设备码过期重试、登录失效和重新授权 | 进度与操作归属当前账号。重新授权一个账号后，另一账号仍使用自己的登录，会显示各自的官方额度。 | 可控双账号隔离测试；目标服务器按实际持有的账号复检 |
| AC-07 | 分别为 DeepSeek 和 MiMo 新增密钥、仅改名、尝试错误新密钥，再替换有效密钥 | 保存后只见末四位。改名和失败替换保留原连接，有效替换后按新密钥验证及查询。 | 浏览器契约测试与服务器连接复检 |
| AC-08 | 关闭网页跨过刷新周期，重开后手动刷新，更改间隔，再重启服务 | 默认 15 分钟后台查询，修改间隔生效。可核实网页关闭期间的更新时间。账号独立更新，重启后保留配置和上次成功结果。 | 可控时钟和服务端查询记录，目标服务器复检 |
| AC-09 | 在相同示例数据下复现四个页面，按两种核准视口对照，再缩至 390 × 844 | 四组构图符合第 3 节。窄屏单列，无页面级横向滚动。缩放或旋转时页签、筛选和未提交的输入都保留。 | 同视口截图、浏览器操作及老板视觉复检 |

**验收证据。** 原型使用示例账号、内存数据和模拟授权，供操作与视觉对照。实施后按项目约定由独立测试员从公开入口复验，记录对应 AC、候选提交、命令和实际结果。老板在目标服务器使用实际持有的 Codex、DeepSeek 和 MiMo 账号，与相近时间的官方数据对照，并核对关闭网页后的后台刷新。双账号隔离必须用两组独立测试身份验证。只有一个真实 Codex 账号时即可完成单账号实测，有第二个真实账号时再补实号隔离对照，分别记录测试与实号证据。视觉风格已核准，服务器成品验收待执行。
