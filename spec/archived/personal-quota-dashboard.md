# 个人订阅额度看板

- 版本 `0.1`
- 状态 `archived`。
- 规格确认记录 2026-11-24，老板确认 Spec 0.1 的范围和验收口径。
- 需求确认记录 2026-11-24，老板确认四项查询、余额展示口径、Windows 本机使用、打开时自动查询、手动刷新、单项失败时保留旧值，以及复用本机登录和配置。

## 目标和范围

个人用户打开一个本机网页，就能判断 ChatGPT 聊天、Codex、DeepSeek 和小米 MiMo 还有多少可用额度或余额。周期性额度有官方重置时间时一并显示。业务用词见[项目术语表](../../GLOSSARY.md)。

1. 我想双击后直接打开看板，日常查额度时可以少开几个平台。
2. 我想看到 Codex 各额度窗口的剩余比例和重置时间，以判断还能继续用多久、何时恢复。
3. 我想从看板进入 ChatGPT 的官方查看入口，账户明确进入共享额度后，可以在看板上直接看到这一份额度。
4. 我想先看 DeepSeek 和 MiMo 的可用余额，需要时再展开充值、赠金和适用的授信明细。
5. 我想在打开页面时看到最新结果，也能主动刷新。
6. 我想在某一项查询失败时看到上次成功的结果和时间，判断数据是否还能作为参考。
7. 我想知道缺的是哪个账号登录或配置，其他已接入的平台可以照常查看。

## 业务行为和验收

| 验收编号 | 关键用例与前置状态 | 公开入口与输入 | 可观察的预期结果 | 验证方式 |
| --- | --- | --- | --- | --- |
| AC-01 | Windows 本机已安装或解包，浏览器可用 | 双击项目提供的启动入口 | 打开本机浏览器中的看板，可以看到额度、余额和官方查看入口。已有服务运行时再次双击仍能打开看板 | 老板人工复检 |
| AC-02 | 测试数据源第一次给出 DeepSeek ¥80，第二次给出 ¥65 | 打开看板，完成自动查询后点击「刷新」 | 打开时自动发起一轮查询并显示 ¥80。点击后再次查询并显示 ¥65，成功时间随结果更新。查询进行时呈现查询状态 | 浏览器契约用例 |
| AC-03 | Codex 返回短、长两个窗口，已用 25% 和 70%，仅短窗口有重置时间 | 打开看板并完成 Codex 查询 | 显示两个窗口各自的剩余比例 75% 和 30%。短窗口显示官方重置时间，长窗口的重置信息显示为未提供 | 浏览器契约用例 |
| AC-04 | 官方来源只返回 Codex 专用窗口 | 打开看板，点击 ChatGPT 聊天的官方查看入口 | Codex 显示自己的额度。ChatGPT 聊天提供跳转到官方站点的入口，聊天剩余值处于需前往官方查看的状态 | 浏览器契约用例 |
| AC-05 | 测试数据明确提供一份覆盖 ChatGPT 与 Codex 的共享额度，剩余 70% 且有重置时间 | 打开看板并完成查询 | 显示一份标明 ChatGPT 与 Codex 共享的额度，数值为 70% 并显示重置时间。同一份额度只出现一次 | 浏览器契约用例，实号按账户返回复检 |
| AC-06 | DeepSeek 返回 CNY 总额 80.00，其中充值 70.00、赠金 10.00，另返回 USD 总额 5.00 | 查看 DeepSeek 卡片并展开明细 | CNY 和 USD 按各自币种显示可用余额，人民币明细分别显示 ¥70.00 和 ¥10.00 | 浏览器契约用例 |
| AC-07 | MiMo SK 账户返回 CNY，现金 100.00、赠金 20.00、可用授信 80.00、官方总额 200.00、冻结 20.00 | 查看 MiMo 卡片并展开明细 | 首屏显示当前可动用 ¥180.00。明细分别显示现金 ¥100.00、赠金 ¥20.00、可用授信 ¥80.00、冻结 ¥20.00 | 浏览器契约用例 |
| AC-08 | 余额查询成功，官方回执确认当前可用额为零；另一次首次查询超时 | 打开看板并观察两种结果 | 成功查到的零额显示为对应币种的 0.00。首次超时显示查询失败状态及可识别的原因 | 浏览器契约用例 |
| AC-09 | 同一 DeepSeek 账户此前成功查到 ¥80 和成功时间，本次超时；其他已配置来源成功 | 点击「刷新」 | DeepSeek 保留 ¥80 和上次成功时间，同时标记「刷新失败」。其他来源正常更新。DeepSeek 随后刷新成功时更新数值及时间，清除失败状态 | 浏览器契约用例 |
| AC-10 | Codex 未登录，MiMo API Key 未配置，DeepSeek 配置有效 | 打开看板 | Codex 提示在本机登录，MiMo 提示补本机配置，DeepSeek 正常显示余额 | 浏览器契约用例 |
| AC-11 | 同一账户此前查询成功，关闭再启动后查询失败；另一轮已能识别凭据对应的账户发生变化 | 再次双击启动，查看对应卡片 | 同一账户保留最后一次成功结果及原时间。识别到账户变化时，该来源按新账户的查询结果或首次查询状态显示 | 浏览器契约用例 |

人工复检由老板在本机进行。双击打开后，核对 Codex 已有登录的额度窗口、DeepSeek 账户余额和 MiMo SK 账户余额。用相近时间的官方数据对照看板的数值与单位。ChatGPT 官方查看入口应打开对应站点。账户已有明确共享数据时，再对照共享剩余量和重置时间。实测回执记录已核对项和当前账户可用的数据。

## 约束与兼容

- Windows 本机浏览器访问本机服务。启动入口负责打开浏览器。Codex 复用本机 CLI 的 ChatGPT 登录，DeepSeek 与 MiMo 复用本机已配置的 API Key。凭据读取和查询发生在本机服务，页面、缓存和日志只接收展示所需的结果。
- Codex 剩余比例由官方的已用比例换算，有值的重置时间按 Windows 本地时间展示。是否共享以可读取且明确标注为共享的账户数据为准。迁移后官方网页可展示共享值，真实账户能否通过本机查询读取该值需现场验收。 [Codex App Server](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt) · [OpenAI 共享额度公告](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits)
- DeepSeek 按接口返回币种显示 `total_balance`，明细使用同币种的充值和赠金余额。 [DeepSeek 查询余额](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)
- MiMo 使用 SK 账户的官方余额接口。看板根据官方可用性判式计算当前可动用金额，用官方总额减冻结金额，结果小于零时可用金额归零。现金、赠金、可用授信和冻结金额按接口原值列在明细。 [MiMo 查询余额](https://mimo.mi.com/docs/zh-CN/api/asset/balance-get)
- 上次成功结果和成功时间保存在本机，按数据来源与可识别的账户绑定。各来源独立更新。一次刷新中成功的来源可以先显示结果，同一来源有重叠查询时，页面以最近发起的查询为准。
